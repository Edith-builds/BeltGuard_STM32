# STM32CubeIDE / CubeMX setup

Reference MCU: STM32F446RET6 on NUCLEO-F446RE. Create a **new board project** and retain SWD. Do not flash onto a different F4/H7 unchanged. HAL, CMSIS startup files and linker script come from the STM32CubeF4 installation. This delivery is source integration, not an `.ioc` falsely implying a confirmed board configuration.

## Pins

| Device | STM32 pins | Configuration |
|---|---|---|
| IIS3DWB | PA5 SCK, PA6 MISO, PA7 MOSI; PB6 CS | SPI1 master, 8-bit, mode 3, software NSS; 5.625 MHz at 90 MHz PCLK2 /16. CS initial high. |
| MFRC522 | PC10 SCK, PC11 MISO, PC12 MOSI; PA4 CS; PC7 RST | SPI3 master, 8-bit, mode 0, software NSS; 2.8125 MHz at 45 MHz PCLK1 /16. CS/RST initially high. Separate bus avoids SPI-mode switching. |
| INMP441 | PB12 WS, PB13 CK, PC3 SD | I2S2 master receive, Philips I2S, 24-bit in 32-bit slots, nominal32 kHz, MCLK off. L/R low selects left channel. |
| HX711 | PC0 DOUT, PC1 SCK | DOUT input; SCK output push-pull initial low. Channel A /128. Use 3.3 V compatible digital levels. |
| Encoder | PA0 TIM2_CH1, PA1 TIM2_CH2 | TIM2 Encoder mode TI1+TI2 (x4), prescaler0, ARR0xFFFFFFFF, rising polarities, filters6 as starting value. Test max speed/filter effect. |
| Laptop | PA2 USART2_TX, PA3 USART2_RX | ST-LINK VCP, 115200,8N1; TX DMA normal mode. |
| Advisory indicator | PB0 | GPIO output initially low; external LED + resistor, never conveyor stop/start input. |
| Debug | PA13/PA14 | SWD retained. |

These pins are a **new explicit reference implementation**, not a claim that the final PDF supplies a pin map. Confirm wiring before connecting earlier CAD/electronics. PA5 is also the board's LD2 connection: do not configure it as an alarm LED while it is SPI1 SCK.

Use a genuine 3.3 V compatible MFRC522 board. “SDA” on many RC522 SPI modules means chip-select, not I2C SDA. NPN open-collector encoder outputs need pull-ups to 3.3 V; never attach a 12/24 V push-pull signal directly. Validate ground/isolation and connector pinouts. Do not feed the deck's 24 V source into MCU/sensor pins. Provide regulated supplies compatible with the actual boards. USB/externally powered Nucleo jumper/backfeed setup follows ST UM1724.

## Clocks, DMA, interrupts

- Use the CubeMX clock calculator to produce SYSCLK180 MHz, AHB180, APB1 45, APB2 90. Follow board HSE-bypass/ST-LINK clock settings or use HSI; do not assume an external crystal is fitted.
- Use the calculator to derive I2S32 kHz. Measure actual WS and update `BG_MIC_FS`; the nominal rate need not be exact. DWT timing uses `SystemCoreClock`, which must be correct.
- I2S2_RX: DMA1 Stream3 Channel0, peripheral-to-memory, **circular**, peripheral increment off, memory increment on, peripheral/memory widths halfword, high priority, half/full interrupts enabled. Check CubeMX for conflicts. The F4 HAL doubles DMA transfer size for 24-bit slots: application buffer1024 halfwords, HAL argument512 words. Each completed half holds128 stereo frames; left channel uses halfword offsets0/1 of each four-halfword frame.
- USART2_TX: DMA1 Stream6 Channel4, normal, memory increment on, byte widths. Enable DMA IRQ **and USART2 global IRQ** (required to finish normal TX after TC). Packet buffer remains static until completion. No RX DMA required.
- Enable I2S/SPI2 error IRQ and forward HAL I2S errors. DMA priority should precede background serial work. No FFT or RFID transaction belongs in an interrupt.
- IWDG: LSI, prescaler64, reload1000 (nominal ~2 s at32 kHz, tolerance applies). Start after peripherals. Debug freeze is useful only during bring-up.
- GPIO clock enables and alternate functions are generated by CubeMX. Set CS pins high before sensor init. Do not enable SPI2 independently of I2S2.

## Add source and include paths

Copy the package into a `BeltGuard/` folder in the project. Compile:

```
BeltGuard/Core/bg.c
BeltGuard/Drivers/mfrc522.c
BeltGuard/Drivers/iis3dwb_reg.c
BeltGuard/STM32/bg_app.c
```

Add `BeltGuard/Core`, `BeltGuard/Drivers`, `BeltGuard/STM32` to C include paths. Exclude `tests` from embedded build. Link `libm` (`-lm`) and enable newlib-nano float formatting (`-u _printf_float`) for telemetry. Use GNU11, optimisation `-O2`, Cortex-M4 hardware single-precision FPU (Cube default hard-float configuration). Set stack to at least4 KB and review linker map; the application uses static buffers and one ~896-byte FIFO burst buffer on the stack. No dynamic allocation is used by application logic.

Configure Cube to generate peripheral initialisation functions and handles named `hspi1`, `hspi3`, `hi2s2`, `htim2`, `huart2`, `hiwdg`. Initialisation sequence in generated main:

```c
#include "bg_app.h"
/* Generated HAL_Init(), SystemClock_Config(), MX_GPIO_Init(), MX_DMA_Init(),
   MX_SPI1_Init(), MX_SPI3_Init(), MX_I2S2_Init(), MX_TIM2_Init(),
   MX_USART2_UART_Init(), MX_IWDG_Init() run first. */
BG_Init();
while (1) {
    BG_Task();  /* no HAL_Delay here: drain sensor FIFO continuously */
}
```

Add these once in a USER CODE section (merge with existing callbacks rather than duplicating them):

```c
void HAL_I2S_RxHalfCpltCallback(I2S_HandleTypeDef *h) {
    if (h->Instance == SPI2) BG_I2SHalf();
}
void HAL_I2S_RxCpltCallback(I2S_HandleTypeDef *h) {
    if (h->Instance == SPI2) BG_I2SFull();
}
void HAL_I2S_ErrorCallback(I2S_HandleTypeDef *h) {
    if (h->Instance == SPI2) BG_I2SError();
}
void HAL_UART_TxCpltCallback(UART_HandleTypeDef *h) {
    if (h->Instance == USART2) BG_UARTDone();
}
void HAL_UART_ErrorCallback(UART_HandleTypeDef *h) {
    if (h->Instance == USART2) {
        HAL_UART_AbortTransmit(h);
        BG_UARTDone();
    }
}
```

I2S hardware/DMA errors latch `mic_errors` and invalidate the current window; if HAL stopped acquisition, restart only after diagnosing/reinitialising it (reset board during first bring-up). The code does not promise autonomous recovery from every clock/DMA fault. The independent watchdog does not prove sensor health: missing sensors yield invalid telemetry while the processor remains alive.

## Configure/calibrate

`BG_CALIBRATED=0` is the shipped default: no fabricated healthy readings or fictitious section identity from placeholder UID values. Raw UID/load telemetry remains available. For a primary node, move the belt, measure full-loop counts and offsets to each tag; choose non-overlapping windows that cover the real read zone. Confirm x4 counts:600 PPR normally means2400 counts/rev in quadrature, but vendors may label CPR differently.

Calibrate load with empty and known-loaded readings:

```
BG_LOAD_TARE = empty raw mean
BG_LOAD_COUNTS_PER_KG = (known loaded raw mean - empty raw mean) / known kg
```

A negative scale is legitimate for reversed load-cell polarity. Zero is invalid. Load-cell saturation is rejected. Stuck-in-range or drift faults need bench tests/redundancy; they cannot be inferred reliably from one ADC alone. Do not auto-tare at boot with an unknown payload.
